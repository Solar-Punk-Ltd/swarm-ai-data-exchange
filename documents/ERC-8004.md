# ERC-8004 Implementation Specification for Swarm Data Exchange POC

This document outlines the architecture and implementation details for the ERC-8004 module of our Swarm Data Exchange Proof of Concept (POC). ERC-8004, officially titled "Trustless Agents," provides the foundational on-chain trust, identity, and discovery layers for autonomous AI agents. By leveraging this standard, our POC enables demo agents to operate as sovereign economic actors without relying on centralized intermediaries.

## 1. Identity Registry (Agent NFT Registration)

The core of our agent identity system is built upon the ERC-8004 Identity Registry, which utilizes the ERC-721 Non-Fungible Token (NFT) standard extended with **`ERC721URIStorage`**. This ensures metadata is not stored in-state; only the URI reference is kept on-chain to maximize gas efficiency.

*   **On-Chain Identity:** Every data provider agent (e.g., the image generating agent or copy trading bot) and consumer agent will be minted as a unique ERC-721 NFT. This provides a globally unique identifier formatted as `{namespace}:{chainId}:{identityRegistry}:{agentId}`.
*   **Agent Card Stored on Swarm:** The identity NFT's `tokenURI` (or `agentURI`) will not store large metadata directly on-chain. Instead, it will point to an "Agent Registration File" (Agent Card) hosted immutably on the decentralized Swarm network. The URI will be formatted as `bzz://<hash>` (a Swarm reference), which the client can easily resolve via a Swarm gateway or their local Bee node.
*   **Agent Card Structure:** The Agent Card is a standardized JSON file acting as the agent's passport. It will contain the agent's name, description, capabilities, and communication/payment endpoints (including the Swarm MCP endpoint and the x402 payment server URL).

## 2. Discoverability Layer

A primary benefit of ERC-8004 is that it creates an open, permissionless directory of agents. Because the Identity Registry acts as a global namespace, we do not need to build a custom discovery UI from scratch for the POC.

*   **Existing Explorers:** We will rely on existing ecosystem tools and discoverability layers, such as `https://8004scan.io`, to browse and filter available agents.
*   **Indexer Integration:** Any indexer can listen to the official on-chain registry events—specifically `Registered (uint256 indexed agentId, string agentURI, address indexed owner)`—extract the `agentURI`, and fetch the full Agent Card from Swarm to populate search interfaces.
*   **Agent-Native Discovery:** Consumer agents utilizing Swarm MCP can programmatically query the registry via the `@solarpunk/erc8004-adapter`'s discovery methods to find providers that match their required data schemas and evaluate their trust signals before initiating an x402 payment.

## 3. Reputation Registry (Feedback & Trust)

Since our agents are operating in a trustless environment and selling data, consumers need a way to verify provider reliability. We will plug in the ERC-8004 Reputation Registry to handle this.

*   **Feedback Authorization:** To prevent unauthenticated or spoofed reviews, an agent cannot simply be rated by anyone. After a consumer successfully pays via x402 and retrieves the ACT-protected Swarm data, the provider agent must issue a cryptographic signature (`feedbackAuth`) authorizing the consumer to leave a review.
*   **On-Chain Scoring & Off-Chain Evidence:** The consumer will call the `giveFeedback` function on the smart contract, submitting a numerical score (0-100) and optional categorization tags directly on-chain. **Note:** The `agentId` used in this function corresponds exactly to the same ERC-721 token ID exposed in the Identity Registry, ensuring the reputation loop connects perfectly to the agent's identity.
*   **Evidence on Swarm:** Detailed textual feedback, execution logs, and cryptographic proofs of the x402 payment will be stored in a JSON file uploaded to Swarm. The Swarm hash (`feedbackURI`) will be anchored in the on-chain transaction to guarantee data integrity.

**Implementation via `@solarpunk/erc8004-adapter`:**
```typescript
// Consumer agent submits feedback after verifying the Swarm ACT payload
await erc8004.reputation.postFeedback({
  agentId: providerAgentId, // The ERC-721 token ID of the provider
  score: 95, // 0-100 score
  tags: ['trading-data', 'reliable'],
  evidenceURI: `bzz://${evidenceHash}`, // Swarm hash of the detailed review JSON
  feedbackAuth: signedAuthPayload // Provided by the seller to prevent spoofing
});

// Other agents can now calculate aggregated reputation before purchasing
const reputation = await erc8004.aggregate.calculateReputation(providerAgentId);
```

## 4. Integration with POC Modules

The ERC-8004 implementation serves as the foundational trust layer that stitches the other POC modules together:
1.  **Demo Agents:** The agents will automatically generate their Agent Cards, publish them to Swarm, and map them to their ERC-721 identity.
2.  **x402 Payments:** Consumer agents will query the Reputation Registry before executing a purchase. **Initially, this will be deployed on a testnet Facilitator (e.g., using USDC on Base Sepolia), with the potential to extend to a Swarm-native Facilitator utilizing the BZZ token if time permits.**
3.  **Data Indexing & Cross-Linking:** The on-chain events emitted by the ERC-8004 registries will be indexed alongside the OntoDAG-based Swarm metadata. The OntoDAG indexing will tag Swarm metadata (like `dataSchema` and `dataCategory`) and directly link it back to the ERC-8004 `agentId`. This guarantees that identity, payment capabilities, and data schemas are entirely cross-linked in a verifiable, decentralized economy.
