# ERC-8004 Implementation Specification for Swarm Data Exchange POC

This document outlines the architecture and implementation details for the ERC-8004 module of our Swarm Data Exchange Proof of Concept (POC). ERC-8004, officially titled "Trustless Agents," provides the foundational on-chain trust, identity, and discovery layers for autonomous AI agents. By leveraging this standard, our POC enables demo agents to operate as sovereign economic actors without relying on centralized intermediaries.

## 1. Identity Registry (Agent NFT Registration)

The core of our agent identity system is built upon the ERC-8004 Identity Registry, which utilizes the ERC-721 Non-Fungible Token (NFT) standard extended with **`ERC721URIStorage`**. This ensures metadata is not stored in-state; only the URI reference is kept on-chain to maximize gas efficiency.

- **On-Chain Identity:** Every data provider agent (e.g., the image generating agent or copy trading bot) and consumer agent will be minted as a unique ERC-721 NFT. This provides a globally unique identifier formatted as `{namespace}:{chainId}:{identityRegistry}:{agentId}`.
- **Agent Card Stored on Swarm via Feed:** The identity NFT's `agentURI` does not store large metadata directly on-chain. Instead, it points to an "Agent Card" hosted on the decentralized Swarm network as a **feed** — a mutable reference that always resolves to the latest version of the card. The URI is a Swarm gateway feed URL (`https://api.gateway.ethswarm.org/feeds/<owner>/<topic>`), meaning the provider can update their Agent Card in the future without ever changing the on-chain URI.
- **Agent Card Structure:** The Agent Card is a standardized JSON file acting as the agent's passport. It contains the agent's name, description, version, capabilities, and communication/payment endpoints (including the Swarm MCP endpoint and the x402 payment server URL).

```typescript
interface AgentCard {
  type: string; // MUST be "https://eips.ethereum.org/EIPS/eip-8004#registration-v1"
  name: string;
  description: string;
  version: string;
  image?: string;
  services: { name: string; endpoint: string; version?: string }[];
  x402Support: boolean;
  active: boolean;
  registrations?: { agentId: bigint; agentRegistry: string }[];
  supportedTrust?: string[]; // e.g. ["reputation"]
  capabilities?: string[]; // e.g. ["trading", "price-feeds"]
}
```

**Implementation via `@solarpunk/erc8004-adapter`:**

```typescript
import {
  createERC8004Client,
  generateAgentCard,
  uploadAgentCard,
} from '@solarpunk/erc8004-adapter';
import { SWARM_AI_CAPABLE } from '@solarpunk/erc8004-adapter/constants';
import { ethers } from 'ethers';

const provider = new ethers.JsonRpcProvider('https://sepolia.base.org');
const signer = new ethers.Wallet(PRIVATE_KEY, provider);

const erc8004 = createERC8004Client({ provider, signer, chain: 'base-sepolia' });

// 1. Build the Agent Card
const card = generateAgentCard({
  name: 'My Data Provider',
  description: 'Sells encrypted image datasets via Swarm',
  version: '1.0.0',
  services: [
    { name: 'x402', endpoint: 'https://provider.example.com/data' },
    { name: 'swarm', endpoint: 'https://swarm.example.com' },
  ],
  x402Support: true,
  capabilities: ['image-data', 'swarm'],
});

// 2. Upload to a Swarm feed — reads BEE_FEED_PK, BEE_API_URL, BEE_POSTAGE_STAMP from env.
//    Using a feed means the card can be updated later without changing the on-chain URI.
const { feedUrl: agentURI } = await uploadAgentCard(card);

// 3. Register on-chain, tagging the agent as swarm_ai_capable for discovery
const { agentId, txHash } = await erc8004.identity.register(agentURI, [
  { metadataKey: SWARM_AI_CAPABLE, metadataValue: new Uint8Array([1]) },
]);
```

### CLI — one-command registration

For registration without writing TypeScript, the `create-agent` CLI handles the full flow (generate card → upload to Swarm → register on-chain):

```sh
pnpm run create-agent \
  --name "My Data Provider" \
  --description "Sells encrypted image datasets via Swarm" \
  --x402 "https://provider.example.com/data" \
  --swarm "https://swarm.example.com" \
  --capabilities "image-data,swarm"
# --privateKey and --feedPrivateKey fall back to PRIVATE_KEY / BEE_FEED_PK env vars
```

Output: `{ agentId, txHash, agentURI }`

## 2. Discoverability Layer

A primary benefit of ERC-8004 is that it creates an open, permissionless directory of agents. Because the Identity Registry acts as a global namespace, we do not need to build a custom discovery UI from scratch for the POC.

- **Existing Explorers:** We will rely on existing ecosystem tools such as `https://8004scan.io` to browse and filter available agents.
- **Metadata-Based Filtering:** Agents signal capabilities on-chain via key/value metadata set at registration time (or updated later). The `swarm_ai_capable` key is the primary discovery signal for this POC — only agents with this flag set to `1` are returned by the discovery flow.
- **Agent-Native Discovery:** Consumer agents can programmatically query the registry via `findAgentsWithMetadata`, which scans `MetadataSet` events, deduplicates to the latest value per agent, and returns each matching agent's on-chain URI.

```typescript
import { ethers } from 'ethers';
import { SWARM_AI_CAPABLE } from '@solarpunk/erc8004-adapter/constants';
import { downloadAgentCard } from '@solarpunk/erc8004-adapter';

// Find all agents with swarm_ai_capable = 1
const agents = await erc8004.identity.findAgentsWithMetadata(SWARM_AI_CAPABLE);
const capableAgents = agents.filter((a) => ethers.toBigInt(a.rawValue) === 1n);

for (const agent of capableAgents) {
  const card = await downloadAgentCard(agent.uri);
  console.log(`agentId: ${agent.agentId} — ${card.name}`);
}
```

### CLI — one-command discovery

```sh
pnpm run discover-agents
# Outputs: [{ agentId, agentURI, agentCard }]
```

To inspect a single known agent by ID:

```sh
pnpm run get-agent --agentId 5102
# Outputs: { agentId, agentURI, agentCard }
```

## 3. Reputation Registry (Feedback & Trust)

Since our agents are operating in a trustless environment and selling data, consumers need a way to verify provider reliability. We will plug in the ERC-8004 Reputation Registry to handle this.

- **Feedback Authorization:** To prevent unauthenticated or spoofed reviews, an agent cannot simply be rated by anyone. After a consumer successfully pays via x402 and retrieves the data, the provider agent must issue a cryptographic `FeedbackAuth` token (EIP-712 signature) authorizing the specific consumer to leave a review.
- **On-Chain Scoring & Off-Chain Evidence:** The consumer calls `postFeedback` on the Reputation Registry, submitting a numerical score (0–100) and optional categorization tags. The `agentId` is the same ERC-721 token ID from the Identity Registry, ensuring the reputation loop connects directly to the agent's identity.
- **Evidence on Swarm:** Detailed textual feedback, execution logs, and cryptographic proofs of the x402 payment are stored in a JSON file uploaded to Swarm. The Swarm hash (`evidenceURI`) is anchored in the on-chain transaction to guarantee data integrity.

**Implementation via `@solarpunk/erc8004-adapter`:**

```typescript
// Provider side — after confirming payment, sign a token authorizing this consumer to review
const feedbackAuth = await erc8004.reputation.signFeedbackAuth(
  providerAgentId,
  consumerAddress,
  3600, // token valid for 1 hour
);
// Pass feedbackAuth to the consumer (e.g. in the x402 response payload)

// Consumer side — after verifying the downloaded data
await erc8004.reputation.postFeedback({
  agentId: providerAgentId,
  score: 95,
  tags: ['trading-data', 'reliable'],
  evidenceURI: `bzz://${evidenceHash}`, // Swarm hash of the detailed review JSON
  feedbackAuth, // EIP-712 token from the provider
});

// Any agent can now check aggregated reputation before purchasing
const reputation = await erc8004.aggregate.calculateReputation(providerAgentId);
// { score: 95, feedbackCount: 1n, reliable: false }
// reliable === true when score >= 70 AND feedbackCount >= 3
```

## 4. Integration with POC Modules

The ERC-8004 implementation serves as the foundational trust layer that stitches the other POC modules together:

1. **Demo Agents:** The agents automatically generate their Agent Cards, publish them to Swarm via a feed, and map them to their ERC-721 identity via the `create-agent` CLI or the SDK directly.
2. **x402 Payments:** Consumer agents query the Reputation Registry before executing a purchase. The `FeedbackAuth` token is passed in the x402 response payload to close the trust loop after payment. **Initially deployed on Base Sepolia with USDC, with the potential to extend to a Swarm-native Facilitator utilizing BZZ if time permits.**
3. **Data Indexing & Cross-Linking:** The on-chain events emitted by the ERC-8004 registries willbe indexed alongside the OntoDAG-based Swarm metadata. The OntoDAG indexing tags Swarm metadata (like `dataSchema` and `dataCategory`) and links it back to the ERC-8004 `agentId`, guaranteeing that identity, payment capabilities, and data schemas are entirely cross-linked in a verifiable, decentralized economy.
