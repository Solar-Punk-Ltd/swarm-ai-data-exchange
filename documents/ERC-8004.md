# ERC-8004 Implementation Specification for Swarm Data Exchange POC

This document outlines the architecture and implementation details for the ERC-8004 module of our Swarm Data Exchange Proof of Concept (POC). ERC-8004, officially titled "Trustless Agents," provides the foundational on-chain trust, identity, and discovery layers for autonomous AI agents. By leveraging this standard, our POC enables demo agents to operate as sovereign economic actors without relying on centralized intermediaries.

## 1. Identity Registry (Agent NFT Registration)

The core of our agent identity system is built upon the ERC-8004 Identity Registry, which utilizes the ERC-721 Non-Fungible Token (NFT) standard extended with `URIStorage`.

*   **On-Chain Identity:** Every data provider agent (e.g., the image generating agent or copy trading bot) and consumer agent will be minted as a unique ERC-721 NFT. This provides a globally unique identifier formatted as `{namespace}:{chainId}:{identityRegistry}:{agentId}`.
*   **Agent Card Stored on Swarm:** The identity NFT's `tokenURI` (or `agentURI`) will not store large metadata directly on-chain. Instead, it will point to an "Agent Registration File" (Agent Card) hosted immutably on the decentralized Swarm network. The URI will use the format `swarm://<hash>`.
*   **Agent Card Structure:** The Agent Card is a standardized JSON file acting as the agent's passport. It will contain the agent's name, description, capabilities, and communication/payment endpoints (including the Swarm MCP endpoint and the x402 payment server URL). 

**Implementation via `@solarpunk/erc8004-adapter`:**
We will utilize the `@solarpunk/erc8004-adapter` library to handle the generation and registration of this file. 
```typescript
import { createERC8004Client, generateRegistrationFile } from '@solarpunk/erc8004-adapter';

// 1. Generate the Agent Card JSON
const regFile = generateRegistrationFile({
  name: 'Trading Data Agent',
  description: 'Sells copy trading data logs on Swarm',
  services: [
    { name: 'x402-endpoint', endpoint: 'https://demo-agent.local/api/data' },
    { name: 'MCP', endpoint: 'https://demo-agent.local/mcp' }
  ]
});

// 2. Upload to Swarm via local Bee node
const regFileHash = await myBeeClient.upload(JSON.stringify(regFile));

// 3. Register the agent on-chain
const { agentId } = await erc8004.identity.register(`swarm://${regFileHash}`);
```

## 2. Discoverability Layer

A primary benefit of ERC-8004 is that it creates an open, permissionless directory of agents. Because the Identity Registry acts as a global namespace, we do not need to build a custom discovery UI from scratch for the POC.

*   **Existing Explorers:** We will rely on existing ecosystem tools and discoverability layers, such as `https://8004scan.io`, to browse and filter available agents.
*   **Indexer Integration:** Any indexer can listen to the on-chain `NewAgent` or `Registered` events emitted by the Identity Registry contract, extract the `agentURI`, and fetch the full Agent Card from Swarm to populate search interfaces.
*   **Agent-Native Discovery:** Consumer agents utilizing Swarm MCP can programmatically query the ERC-8004 registries to find providers that match their required data schemas and evaluate their trust signals before initiating an x402 payment.

## 3. Reputation Registry (Feedback & Trust)

Since our agents are operating in a trustless environment and selling data (like images or trading logs), consumers need a way to verify provider reliability. We will plug in the ERC-8004 Reputation Registry to handle this.

*   **Feedback Authorization:** To prevent Sybil attacks and review spam, an agent cannot simply be rated by anyone. After a consumer successfully pays via x402 and retrieves the ACT-protected Swarm data, the provider agent must issue a cryptographic signature (`feedbackAuth`) authorizing the consumer to leave a review.
*   **On-Chain Scoring & Off-Chain Evidence:** The consumer will call the `giveFeedback` function on the Reputation Registry smart contract, submitting a numerical score (0-100) and optional categorization tags directly on-chain for high composability.
*   **Evidence on Swarm:** Detailed textual feedback, execution logs, and cryptographic proofs of the x402 payment will be stored in a JSON file uploaded to Swarm. The Swarm hash (`feedbackURI` / `evidenceURI`) will be anchored in the on-chain transaction to guarantee data integrity without bloating blockchain state.

**Implementation via `@solarpunk/erc8004-adapter`:**
```typescript
// Consumer agent submits feedback after verifying the Swarm ACT payload
await erc8004.reputation.postFeedback({
  agentId: providerAgentId,
  score: 95, // 0-100 score
  tags: ['trading-data', 'reliable'],
  evidenceURI: `swarm://${evidenceHash}`, // Swarm hash of the detailed review JSON
  feedbackAuth: signedAuthPayload // Provided by the seller after x402 payment
});

// Other agents can now calculate aggregated reputation before purchasing
const reputation = await erc8004.aggregate.calculateReputation(providerAgentId);
```

## 4. Integration with POC Modules

The ERC-8004 implementation serves as the foundational trust layer that stitches the other POC modules together:
1.  **Demo Agents:** The LangGraph/Docker agents will automatically generate their Agent Cards, publish them to Swarm using the `swarm-cli` or Swarm MCP, and map them to their ERC-721 identity.
2.  **x402 Payments:** Before transferring USDC via the testnet facilitator, consumer agents will query the Reputation Registry to ensure the provider has a positive track record. Once payment settles and Swarm ACT access is granted, the x402 receipt is packaged into the reputation feedback evidence.
3.  **Data Indexing:** The on-chain events emitted by the ERC-8004 Identity and Reputation registries will be indexed (e.g., via The Graph) alongside the OntoDAG-based Swarm metadata, allowing for a fully verifiable, decentralized data economy where identity, payment, and data access are completely permissionless.
